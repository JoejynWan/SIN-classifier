### `sc_utils/sin_classifier.py`

Follows the "adapter lives in the consumer repo" precedent of `sc_utils/speciesnet_classifier.py`.

- Detects Plain vs RSG **from the `state_dict`**, cross-checks against
  `hyper_parameters['model_name']`, and raises on disagreement rather than guessing.
- Reads class names from `hyper_parameters['id_to_labels']`, never hardcoded. **Index order is
  authoritative and must not be sorted** — labels 0–34 are alphabetical but `Porcupines
  (Hystricidae)` was appended at 35, so sorting shifts one class silently.
- **Plain path** delegates to upstream `CustomWeights`.
- **RSG path** swaps in a vendored `NormedLinear` head, drops 12 training-only keys
  (`net.feature.RSG.*` + `net.criterion_cls.weight`) and tolerates 2 unused ones
  (`net.feature.fc.{weight,bias}`). `strict=False` is unavoidable, so both key sets are
  asserted explicitly — anything else raises.
- Reads `loss_type` to decide the logit scale: `30×` for LDAM, none for CE/Focal.

## 3. What the two checkpoints actually contain

Both from run `SINClassifierV2_20250604`, both 36 classes, identical `id_to_labels`:

| | Plain | RSG |
|---|---|---|
| path | `models/Plain_SINClassifierV2_20250604/version_5/…epoch=181-valid_mac_acc=57.98.ckpt` | `models/RSG_SINClassifierV2_20250604/version_14/…epoch=196-valid_mac_acc=34.56.ckpt` |
| head | `nn.Linear` `(36, 2048)` + bias | `NormedLinear` `(2048, 36)`, no bias |
| `loss_type` | `CE` | **`CE`** |
| macro val acc | **57.98** | 34.56 |

**The RSG checkpoint has a structural confidence problem.** It trained with CE on *unscaled*
cosine logits, so its outputs live in `[-1, 1]` before softmax and confidence is capped:
measured max **0.174** in the absolute best case, ~0.05 realistically. Consequences:

- Absolute confidence thresholds are meaningless on it, and not comparable to Plain or SpeciesNet.
- **Not merely cosmetic:** `smoother.py:111` averages the confidence vector across frames *then*
  argmaxes, and averaging does not commute with a softmax temperature change — so the wrong
  scale changes *which class wins*, not just the number.
- Applying `s=30` to "fix" it would be wrong; the model was not trained that way. Any rescaling
  is post-hoc calibration and must be labelled as such.

Between that and the 23-point accuracy gap, **Plain is the default**. RSG is supported and
loads correctly, but is not recommended.

## 4. Corrections made to the earlier plan

The plan was written before the checkpoints were inspected. Three claims were wrong:

1. **RSG has no `net.feature.fc.*` keys at all** — the plan said they existed at a different
   shape and had to be dropped. `rsg_resnet.ResNet.__init__` never builds an `fc`, so they are
   *missing* keys to tolerate. Opposite handling.
2. **The filter list missed `net.criterion_cls.weight`** (the DRW class-weight buffer).
3. **`loss_type` is `CE` on both checkpoints**, not LDAM. `config_classify.yaml` says `LDAM`;
   the checkpoints disagree and win. So no `s=30`.

Also corrected during implementation:

- The plan said **3** tolerated keys; it is **2** — `NormedLinear` has no bias, so the model
  never expects `net.classifier.bias` either.
- The plan said `all_confidences` pairs class **ids** "matching `CustomWeights`";
  `CustomWeights` actually emits class **names** (`self.CLASS_NAMES[i]`). The code follows the
  real format. Note this differs from `SpeciesNetInference`, which does pair ids — harmless,
  since only element `[1]` is read now that `all_class_id` is gone.

**One bug introduced and caught:** `max_confidence()` originally returned the 0.174 cosine
ceiling for the Plain head too, which is false — Plain is unbounded and scored 0.9255 on the
same input. It now returns `None` for Plain.

## 6. Known blockers and things deliberately not done

1. **`single_image_detection(verbose=...)` — outstanding, and yours.**
   `PytorchWildlife_Vid.py:54` passes `verbose=False`, but the fork's
   `YOLOV8Base.single_image_detection` has no such parameter. It was a CameraTrap-side
   customization (`917231a6 "Add verbose argument for consistency"`) that never migrated. You
   said the fix exists locally on the other desktop and is unpushed, so **the call site was left
   unchanged on purpose**. Until that lands, this machine needs a shim forwarding `verbose` onto
   `self.predictor.args.verbose`. Without it, ultralytics logs one line per frame.
2. **Latent upstream bug in the Pytorch-Wildlife fork.** `megadetectorv6.py:49` sets
   `MODEL_NAME = "MDV6b-rtdetr-c.pt"`, but `yolov8_base.py:63` tests for `'MDV6b-rtdetrl.pt'`
   when choosing `RTDETRPredictor` over `DetectionPredictor`. The strings do not match, so
   `DET_VERSION: 'MDV6-rtdetr-c'` would silently use the wrong predictor. Not hit by the current
   config (`MDV6-yolov9-c`). Not fixed — it is in the fork, not this repo.
3. **`CameraTrap2` left untouched**, as agreed. `PW_FT_classification` / `PW_FT_detection` still
   live there and are still the training-side source of truth.
4. **Detector weights download into the repo root.** A `MDV6-yolov9-c.pt_*.tmp` (and eventually
   the `.pt`) lands in the working directory. `.gitignore` only covers `weights/*`, so these
   show as untracked. Do not commit them.
